# Pocket Bullseye: five-person first-use study

Prepared 16 September 2026. **Status: protocol ready; no participants observed yet.**

Recruit five people unfamiliar with Pocket Bullseye who already understand basic chart reading. Include an ordinary older iPhone and a recent iPhone across the group. Use the published web version first; repeat the essential navigation and file-sharing tasks on the prepared native build before its release.

Allow about 25 minutes per session. Explain that the interface is being tested, not their trading ability. Use approved chart fixtures or charts the person chooses to share; hide account details. Ask permission before any recording. Use participant codes P1–P5, not names, in the observations. Do not place trades or ask participants to judge investment profitability.

## Tasks and success criteria

| Task prompt | What to observe | Unassisted success |
|---|---|---|
| “Try the example and explain what the app is telling you.” | First useful action, hesitation, whether the fictional sample is understood | Identifies snapshot status, a finding and something still uncertain. |
| “Use this approved chart to get a reading.” | Upload selection, permission wording, wait comprehension and recovery | Reaches a readable result or correctly explains a visible inability to analyse. |
| “Show me where one of these levels came from.” | Taps selected level, source image and highlight | Opens the correct original screenshot; recognises when no marker is available. |
| “Do the available timeframes tell the same story?” | Comparison discovery, disagreement, readiness | Identifies agreement/conflict without calling it a guaranteed probability; opens a ready report. |
| “Return to this saved setup with a later chart.” | Notebook discovery, comparison sequence and original preservation | Opens the saved decision, supplies the later image and locates the changed evidence. |
| “Write a lesson and find it again.” | Note versus AI suggestion, tag/search behavior | Saves a personal lesson, filters/searches and retrieves it. |
| “Keep a copy you could restore later.” | Export scope, share/download, restore preview | Exports, understands filters and privacy, and restores into a test notebook without losing existing records. |

For expensive scan/review tasks, use the agreed test entitlement and approved fixtures; never record a simulated provider response as a successful live scan. Test restore only with a backed-up/test notebook.

Stay quiet initially. Ask “What would you try next?” after a pause. Mark any intervention as assisted; do not count it as unassisted completion. After tasks ask what they would return for, what felt untrustworthy, and whether motion helped or obstructed reading.

## Device checks alongside sessions

Check portrait/landscape, browser zoom/larger text, motion on/off, reduced-motion preference, visible focus, long instrument names, one-sided/missing levels, pending/failed timeframe switching and slow-network recovery. Verify source images keep their aspect ratio and numeric level anchors do not drift with motion. Test export/share cancellation, a malformed backup, duplicate restore and a conflicting restore on disposable records.

Measure responsiveness and battery/thermal behavior on actual phones before making claims. Distinguish webpage paint/input/layout measurements from AI completion time. Pause and record any blocked route rather than marking it passed.

## How to use the findings

Fix reproducible task blockers first, then repeated misunderstandings, then cosmetic preferences. A five-person study can reveal usability problems; it cannot estimate paid retention or establish statistical conversion lift. Keep the indices acquisition message stable while collecting this evidence. Re-test the affected task after a fix and keep the original observation.
