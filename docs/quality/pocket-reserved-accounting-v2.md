# Reserved-cost accounting v2 — isolated successor to PR119

No paid testing, persistent staging installation or production change is enabled by this patch.

The original database reservation ceiling, unique approval and financial settlement veto remain. The migration now also supports receipt-backed **FULL_RESERVATION_HELD** accounting, explicitly returning `financially_settled:false` and `actual_microusd:null`. Submitted calls retain their complete reservation even after smaller independently attested actual charges; disable/re-enable never refunds it. Only a never-submitted unused slot may be voided. Unknown/time-out/missing-receipt calls block progression. Six synthetic cases are QA, not scanner accuracy evidence.

The new read RPC makes provisional stored measurements available after complete bounded primary receipts (and a receipt or legitimate unused-slot void for rescue). It is a separate result from the original financial release RPC. It must never be presented as billing reconciliation or release acceptance. Existing callers still use the old financial veto until explicitly integrated with this distinction.

## Trust and activation

Budget configuration is DBA-inserted, RLS-protected and append-only; application roles cannot insert or modify it. Each version binds ledger/project/candidate/staging/key fingerprint, reviewed evidence, exact snapshot and a maximum 24-hour verification window. The latest version wins; an expired or future version fails closed. Re-verification appends evidence and cannot reset reservations, change the owner approval or expand the $5 allowance. No real configuration or approval rows are seeded by this migration.

This narrowly reviewed price card accepts only `gpt-5-mini-2025-08-07`, `default`, with output ceilings 7000/1400/1400. At published $0.25/M input and $2/M output, a conservative 400,000-input-token context per call reserves 114000/102800/102800 micro-USD. This includes the entire image/text/schema context without cache discount: 319600/case and 1917600 for six fully dispatched cases. These are maximum budget commitments, not incurred costs. Any rate/model/endpoint/tool/retry change requires fresh review; do not infer current pricing from these constants. A submitted call above either its usage envelope or aggregate budget is held.

`POCKET_BENCHMARK_ACCOUNTING_MODE=full-reservation-v2` opts the existing server scope into metadata verification, reviewed binding comparison and reserved accounting. No flag is set by the patch. All existing pilot and real-dispatch holds remain. Exact model overrides must be pinned; default aliases fail metadata verification. The original settlement RPC still requires independent request-attributed dollar attestation, including for $0.

## Secure runtime verification

Run `node scripts/verify-pocket-benchmark-runtime.mjs` **only inside the isolated staging runner that already has the intended runtime Secret**. Use existing read-only administrator credentials through a secure ephemeral environment, never chat, a browser field, committed file or production deployment. The verifier makes only three HTTPS GET metadata requests to fixed `api.openai.com` routes: project, project key inventory and exact model access. It sends the actual runner key only to the model metadata endpoint with explicit org/project headers. It performs no inference request, redirects, retries, key creation or account changes.

It rejects production/foreign backend URLs, non-project keys, mismatched project/key/model, disabled probes, incomplete inventory, inactive/expired keys, ambiguous redacted matches, alternative SDK base URLs and inconsistent SDK org/project overrides. Output contains non-secret identity metadata and a SHA-256 key fingerprint. Key tracking is explicitly identified as **unique redacted metadata correlation plus project authorization**, not a cryptographic provider signature or per-request billing evidence. A separate authorised reviewer must compare the retained live evidence and insert the matching configuration; the app cannot self-approve it. A successful model metadata read verifies access, not every inference tier or future billing price.

Runtime access prerequisites: existing `OPENAI_API_KEY` and `OPENAI_ADMIN_KEY`, exact previously verified org/project/key, `NEXT_PUBLIC_SUPABASE_URL` for `pxlqvaddvghjjhenqmdh`, exact `POCKET_BENCHMARK_CANDIDATE_SHA`, both exact model overrides, and explicit `POCKET_BENCHMARK_RUNTIME_METADATA_ENABLED=true`. Do not copy a production Secret to satisfy this. Missing secure access is an operational blocker; synthetic tests are not a successful live binding check.
